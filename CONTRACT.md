# Implementation contract

Java 17, Maven, Spring Boot 3.5.16, Spring JDBC, Flyway, PostgreSQL, Kafka, Redis. Three independent boot applications; each has its own PostgreSQL database. Package root `com.wenqi.fulfillment`. All applications scan this package, including common configuration. Import `classpath:application-common.yml` from application.yml. Common Flyway migration location `classpath:db/common`, own migrations `classpath:db/migration`, own start at V2. No JPA, Lombok or H2 substitutes for PostgreSQL.

All APIs other than actuator health require `X-API-Key` equal to `APP_API_KEY` (minimum 32 characters). This is an internal/B2B scoped service identity, not consumer account authentication. Local secrets generated by script, not committed. `app.api-key` property; common config validates it at startup. Ports inventory8081, payment8082, order8080. Database env `DB_URL`, `DB_USER`, `DB_PASSWORD`; Kafka `KAFKA_BOOTSTRAP_SERVERS`. Common API `ApiException(HttpStatus status, String code, String message)`. `Events.append(topic, key, EventEnvelope)` requires an active DB transaction. `EventEnvelope(UUID eventId, String type, int schemaVersion, String aggregateId, Instant occurredAt, JsonNode payload)`; `EventEnvelope.of(type, aggregateId, payload, ObjectMapper)` factory. Outbox publisher is supplied by common. Topic `fulfillment.events.v1` for domain events; `warehouse.status.v1` for warehouse events. Common Kafka templates are String/String (JSON); no Java class headers.

Shared DTOs in `com.wenqi.fulfillment.common.Api` (nested records). IDs UUID; monetary amounts integer long cents, USD only; maximum total 1_000_000_000_000. No floats.

* `LineItem(String sku, int quantity)`.
* `CatalogItem(String sku, String name, long unitPriceMinor, String currency, long version)`.
* `ItemInput(String sku, String name, long unitPriceMinor, String currency, int initialStock)`.
* `StockView(String sku, int onHand, int reserved, int available)`.
* `ReserveRequest(List<LineItem> items)`.
* `ReservationView(UUID orderId, String status, List<LineItem> items)`; statuses RESERVED,COMMITTED,RELEASED.
* `QuoteRequest(List<LineItem> items)`; `QuotedItem(String sku,int quantity,long unitPriceMinor,String currency)`; `QuoteResponse(List<QuotedItem> items,long totalMinor,String currency)`.
* `PaymentRequest(long amountMinor,String currency,String paymentToken)`; `PaymentView(UUID orderId,String status,long amountMinor,String currency,String providerReference)` statuses APPROVED,DECLINED. Fake provider tokens `tok_approved`, `tok_declined` only. No raw cards/real charges. Request identity includes amount,currency,token; changed retry409.
* `CreateOrderRequest(List<LineItem> items,String paymentToken)`; header `Idempotency-Key` required, max128.
* `OrderView(UUID id,String status,List<QuotedItem> items,long totalMinor,String currency,String workflowStep,int attempts,String failureCode,long warehouseSequence,Instant createdAt,Instant updatedAt)`.
* `WarehouseUpdate(UUID eventId,UUID orderId,long sequence,String status)`; statuses PACKED,SHIPPED,DELIVERED, positive sequence. Ingestion creates transactional outbox event type `warehouse.status.updated`, aggregateId order UUID, payload WarehouseUpdate.

Inventory endpoints:
* POST /v1/items ItemInput ->201 CatalogItem (create only, duplicate409). GET /v1/items/{sku} cache-aside CatalogItem; GET /v1/stock/{sku} always DB StockView. Catalog cache is bounded-stale display data, NEVER checkout authority. Redis outages must fall back to DB. Cache on/off env `INVENTORY_CACHE_ENABLED`.
* POST /internal/quotes QuoteRequest ->QuoteResponse, always PostgreSQL authoritative pricing; normalize/sort SKUs, reject duplicates/empty/invalid quantities.
* PUT /internal/reservations/{orderId} ReserveRequest ->ReservationView. Atomic all-or-nothing multi-item reservation, row locks sorted SKU order, no oversell. Retry same items same result; different request409. POST /internal/reservations/{orderId}/commit or /release idempotent. RESERVED→COMMITTED decrements on_hand and reserved; RESERVED→RELEASED decrements reserved only; no COMMITTED↔RELEASED transitions. Persist audit events in same DB transaction.

Payment must first commit an immutable PENDING intent and request fingerprint before invoking the provider. A timeout leaves PENDING; changed retry returns409 without calling provider; same request retries with stable order UUID provider idempotency key. Do not hold the first intent transaction open across the provider call.

Payment endpoint: PUT /internal/payments/{orderId} PaymentRequest ->PaymentView. Idempotent with durable result and request fingerprint. Provider interface and explicitly named simulated local adapter. POSTGRES locks/advisory locks serialize same order under retries. Publish result event with outbox atomically. No claim of PCI compliance or real payment integration.

Order endpoints:
* POST /v1/orders CreateOrderRequest Idempotency-Key ->201 OrderView, replay same request200; changed payload409. Validate tokens before accepting. Calls authoritative inventory quote then persist quote/order/outbox in tx; do not keep external HTTP inside initial create tx. Unique idempotency handles concurrent callers.
* GET /v1/orders/{id} OrderView. GET /v1/orders?limit=20 (max100) ->list.
* POST /v1/orders/{id}/retry ->OrderView ONLY parked workflow; operator recovery.
* POST /v1/warehouse/events WarehouseUpdate ->202 {"eventId":"..."}; transactional outbox then Kafka consumer applies update, never synchronous order-status update. Changed replay eventId409. Consumer atomically stores dedup receipt + updates order in DB tx. Ignore stale sequence and backwards states. Must defer/throw if order not confirmed yet; don't silently consume early update. Consumer failures bounded retries then DLT, documented replay via outbox event ID. Keep same eventId on replay.

Order durable saga worker steps RESERVE→PAYMENT→COMMIT→DONE; on insufficient stock CANCELLED; on declined payment COMPENSATE inventory release→CANCELLED. Transient HTTP errors leave durable step with exponential next-attempt; never compensate payment timeout because outcome unknown. Idempotent dependency APIs allow crash-after-effect-before-step-persist recovery. SELECT FOR UPDATE SKIP LOCKED, one step per tx with bounded HTTP timeouts. Park MANUAL_REVIEW after configured attempt limit; /retry resumes persisted step. Workflow statuses PENDING,CONFIRMED,CANCELLED,MANUAL_REVIEW and later warehouse PACKED,SHIPPED,DELIVERED. Add events through outbox. No automatic release after successful charge/commit.

Tests: meaningful business tests and PostgreSQL integration tests. Tests with `IT` suffix run under Maven profile `integration`/Failsafe with Testcontainers on CI (Docker available); Docker is running. Tests may use external TEST_DATABASE_URL (JDBC), TEST_DATABASE_USER and TEST_DATABASE_PASSWORD; otherwise Testcontainers. Use JUnit5/Mockito from starter-test. Inventory must test concurrent same-order and oversell with real PostgreSQL in IT; order test crash/retry, unknown payment outcome, consumer dedup+sequence+DB rollback. Testcontainers dependency supplied in each app POM if needed.

Infra teammate owns compose.yaml, Dockerfile, .github/workflows, infra/, scripts/ deployment/load scripts, docs/ operations. Root owns common/ and root pom, native local harness and final documentation/review. Service teammates own their service directories only. Coordinate shared contract changes with root.
